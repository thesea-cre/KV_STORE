# 测试引擎结果记录

> 测试工具：`engine/test_engine.c`（函数指针表统一驱动三个引擎）+ `engine/Makefile`（AddressSanitizer 默认开启）
> 运行方式：`make -C engine run`
> 最终结果：**三引擎（kv_array / kv_hash / kv_rbtree）全部用例通过，ASan 零报告（无越界、无泄漏）**

## 结论

- **kv_rbtree.c（红黑树引擎）**：行为断言与内存管理全部干净，无需修复。
- **kv_array.c（数组引擎）**：发现 8 个 bug，全部修复。
- **kv_hash.c（哈希引擎）**：发现 5 个 bug，全部修复。

---

## kv_array.c（8 个）

| # | 位置 | 问题 | 后果 | 修复 |
|---|---|---|---|---|
| A1 | kv_array_create | table malloc 后未清零 | set 靠 `key==NULL` 找空位，table 里是 malloc 垃圾 → set 永远以为 key 已存在，全返回 1。之前"能跑"纯属 glibc 新堆页被内核零化的运气 | malloc 后 `memset(table, 0, ...)` |
| A2 | kv_array_destory | 只 free table | 所有 key/value（深拷贝出来的）全部泄漏 | 遍历 free 非 NULL 的 key/value 再 free table |
| A3 | kv_array_mod | 替换 value 前不 free 旧值 | 每次 mod 泄漏一份旧 value | 替换前 `kv_free` 旧值 |
| A4 | kv_array_set | 扫描循环里 `strcmp` 在 NULL 判断**之前** | del 留下的空位（key=NULL）一进 strcmp 就崩溃 | 先判 `key==NULL` 再 strcmp |
| A5 | kv_array_set | 扫描跑完后 `i==total`，此时读 `table[i].key` 没有边界保护 | total==128（满）时再 set，读 `table[128]` **越界**（ASan 抓获：READ of size 8，2048 字节区右边界） | 循环条件加 `i<KV_MAX_ARRAY`，删除循环后的裸读 |
| A6 | kv_array_set | 插入后无条件 `total++` | 插入空位复用（j<total）时 total 虚增，逐渐漂过 128 → 扫描越界更容易触发 | 只有插在末尾（j==total）才 `total++` |
| A7 | kv_array_set | 满了才返回 -1，但 kcopy 已经分配 | 满时插入泄漏 kcopy | 满判定移到 malloc 之前 |
| A8 | kv_array_mod | 用"第一个空位下标"当"未找到 key"的标记 | 有空洞时 mod 不存在的 key 返回 0（假成功），value 塞进 key 为 NULL 的槽位：get 永远读不到 + 内存泄漏 | 改用独立的 `found` 标记 |

## kv_hash.c（5 个）

| # | 位置 | 问题 | 后果 | 修复 |
|---|---|---|---|---|
| H1 | KV_Map_get | while 循环里 node 不前进 | 查询不存在的 key 且落在**非空桶**时死循环（测试第一次运行未触发仅因 "nope" 恰好落在空桶） | 没找到则 `node=node->next` |
| H2 | KV_Map_mod | 直接 `strncpy(node->value, value, strlen(value))` 进旧缓冲区 | 新值比旧值长时**堆溢出**（ASan 抓获：往 4 字节区写 31 字节） | free 旧 value → malloc 新缓冲区 → 拷贝（对齐 rbtree 的写法） |
| H3 | KV_Map_del / KV_Map_destory | 释放节点时不 free node->key/value | 全部泄漏 | 释放节点前先 free key/value |
| H4 | KV_Map_set | 链上追加（else 分支）漏 `hash->count++` | count 统计不准（只统计了空桶首插） | 补上 |
| H5 | KV_Map_destory | 循环里 `hash->table[i]=node` 写错对象 | 无害但误导，属笔误 | 随 H3 修复一并删除 |

## 未修复/说明

- `KV_Map` 固定 128 桶 + 链式冲突，无扩容设计；`INIT_CAP` 是死宏——**设计选择**，非 bug，未动。
- 测试用例中 `"KKO"`（ASCII 和 219，与 10 个冲突 key 同桶且不存在）专用于回归 H1 死循环。
- 测试覆盖边界：CRUD 语义一致性（三引擎返回码强制一致）、容量上限（array 满 128 拒插）、哈希冲突、2000 规模增删、destory 重建、ASan 内存安全 + 泄漏。**未覆盖**：NULL 参数全组合、性能压力。
